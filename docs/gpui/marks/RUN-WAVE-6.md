Then the speed (above), and the whole once: `cargo test --workspace --no-fail-fast` and `cargo clippy --workspace --all-targets -- -D warnings`.

**Every agent is told these, which the last waves learned the hard way:**

- **No command that walks a drive.** An agent once ran `find / -name …` and two of those were still running nine hours later. To find a file use the search tools, inside the repository; for a crate's source, `cargo metadata`. Before its last message an agent stops every process it started.
- **A build of one agent can meet another's half-written file.** Wait and build again; don't touch the other's file. A build that has waited ten minutes on the lock is said in the report rather than waited on.
- **File-heavy tests that seem to hang** may be the PC (above): time small writes before calling it a bug, and don't trust a timing failure from such a window.
- **Backslashes**: a script passed inline to a shell can lose half its backslashes on the way. Edit files with the editing tools.
- **Tests never touch the PC's own Glint data**: a test that writes marks uses a folder of its own and a ledger of its own (as `marks::apply`'s tests do), never the shared ledger in Glint's data folder.
- A test is run by its own filter (`cargo test -p <crate> <module>::`), not the whole workspace, until the end.
